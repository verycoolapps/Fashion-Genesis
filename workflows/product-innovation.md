# MODES B / C / D — PRODUCT INNOVATION & CATEGORY ATTACK

## PURPOSE

Deep-dive invention on ONE product or ONE category. Three entry variants:

- **Mode B — Category Revolution:** user names a category ("revolutionary handbag",
  "the future of sneakers"). Attack the whole category.
- **Mode C — Function-First:** user names a problem ("shoes that solve X", "a bag
  for people who…"). Start from the problem.
- **Mode D — Aesthetic-First:** user names a visual direction ("futuristic luxury
  bio", "brutalist streetwear"). Start from the mood.

All three converge on the same engine and the same Master Output Format.

## TRIGGERS

- "revolutionary [product]", "rethink [category]", "disrupt [category]"
- "solve [problem]", "for people who [pain point]"
- "[mood/visual direction] [product]", "design something that looks like…"

## DECISION TREE — WHICH VARIANT

```
User names a CATEGORY?          → Mode B (Category Revolution)
User names a PROBLEM/USER?      → Mode C (Function-First)
User names a MOOD/AESTHETIC?    → Mode D (Aesthetic-First)
User names BOTH problem + mood? → Run C for mechanism, then check D coherence;
                                  if they conflict, ask ONE question or pick
                                  function-first and flag the tension.
```

Signals that override the label:
- "revolutionary X that solves Y" → Mode C with category context (B's attack
  method still runs, but the problem drives selection).
- "looks like Z but must do W" → Mode D generates forms, Mode C validates function;
  ship the synthesis, disclose which constraint won.

## MODE B — CATEGORY ATTACK METHODOLOGY

The full 8-step attack. Do every step; compress depth, never skip.

### Step B1 — Define the category boundary

State exactly what counts as "in scope." Handbag includes totes, clutches,
backpacks? Sneakers include slides? Draw the boundary explicitly — it controls
the convention list.

### Step B2 — Map the 10 most sacred conventions

List the 10 conventions the category treats as immutable. Sources: dominant
products, retail taxonomy, user expectations, manufacturing habits. For each
convention write WHY it exists (what problem it solves). Conventions without a
real reason are the best destruction targets.

Example — handbag conventions: must hang on shoulder; opening must be top-access;
interior is hidden; materials are leather/canvas/synthetic; hardware is decorative;
it carries personal items; it has a fixed shape; it closes with zipper/flap/clasp;
it is carried by hand or strap; it is made for one body size range.

### Step B3 — Destroy 3 conventions

Pick the 3 whose destruction creates the most new value (not just novelty).
For each: state the convention, the destruction, and the capability it unlocks.
Write the destruction as a product-level claim, not an aesthetic one.

### Step B4 — Mutate the remaining 7

For each surviving convention, run functional/aesthetic/experience mutation:
keep the convention's PURPOSE but change its FORM. A zipper can become a
pressure-seal; "top access" can become side-entry; "hidden interior" can become
visible modular cells.

### Step B5 — Cross-industry fusion pass

Pick 2 foreign disciplines most relevant to the destroyed conventions. Extract
ONE mechanism each that solves a real problem the category ignores today.

### Step B6 — Synthesis

Fuse destruction + mutation + fusion into 3 candidate product architectures.
Each candidate must name which conventions it destroys and which it keeps.
Reject candidates that are visually loud but functionally hollow.

### Step B7 — Select + stress-test

Score candidates on: convention-destruction count × functional payoff ×
manufacturing plausibility × user clarity. Pick winner. Run Anti-Slop Gate,
Human-Centered Safety, 100-point score.

### Step B8 — Full output

Master Format A–M. In section C (What Makes It Different), explicitly enumerate:
conventions destroyed · conventions mutated · conventions kept · why the mix
creates a new category behavior.

## MODE C — FUNCTION-FIRST (Problem → Invention)

### Step C1 — Problem extraction

Restate the user's problem in one sentence. If vague ("shoes that are comfy"),
sharpen it: WHO has the problem, WHEN does it occur, WHAT does it cost them.
Ask at most ONE clarifying question; otherwise make stated assumptions.

### Step C2 — Needs decomposition

Break the problem into functional needs: physical (support, protection,
thermoregulation), cognitive (attention, wayfinding), social (status, inclusion),
emotional (confidence, calm). Mark which needs the problem actually demands —
not all needs deserve a product response.

### Step C3 — Convention map of the current solution space

What products currently address this problem? List 3–5. For the dominant one,
run a mini category attack: its 5 sacred conventions, which ones fail the user.

### Step C4 — Invention search

For each unmet need, run the mutation engine: what mechanism from another
discipline solves it? Generate 3 mechanism candidates per need; fuse the best
into ONE product concept. The product may solve 1–3 needs deeply — never 10
shallowly.

### Step C5 — Validate the job

Write the "job statement": "When [situation], user wants to [motivation], so they
can [outcome]." If the invention doesn't improve the outcome, redesign — do not
polish.

### Step C6 — Output

Master Format A–M with extra emphasis on section F (Functional Mechanism) and
section H (User Experience). Include the needs-decomposition table in section B.

## MODE D — AESTHETIC-FIRST (Mood → Product)

### Step D1 — Mood extraction

Translate the user's visual direction into concrete principles. "Futuristic
luxury bio" → principles: organic geometry, matte biological textures, restrained
palette, precision without coldness. Write 4–6 principles, each testable
("uses curved not angular silhouettes" is testable; "feels futuristic" is not).

### Step D2 — Anti-reference check

Name 2–3 existing products/designers this mood could collapse into. The design
must be distinguishable from them — otherwise it's a reskin (Level 1–2).

### Step D3 — Aesthetic mutation engine

Run Stage 4 (Aesthetic Mutation) aggressively: silhouette, proportion, volume,
texture, geometry, color logic. Produce 3 form-directions that all satisfy the
principles but differ structurally.

### Step D4 — Function retrofit

For each form-direction, ask: what does this shape DO? A garment that is only a
shape is a sculpture. Assign each direction a real function (silhouette serving
mobility, volume serving storage, geometry serving adjustability). If a direction
has no honest function, it dies here — this is the Anti-Slop Gate applied early.

### Step D5 — Select + synthesize

Pick the direction with strongest form×function fusion. Run full mutation engine
for mechanism depth. Deliver Master Format A–M. Section D (Visual Design) gets
extra depth: describe the form-language rules a whole product line could follow.

---

## CROSS-MODE RULES

- Every mode ends with the same gates: Anti-Slop, Originality Audit,
  Human-Centered Safety, 100-point score, 3-variant evolution.
- "Category Revolution" does not mean attacking ALL conventions — destroying 3
  well-chosen ones beats demolishing 10 and ending with noise.
- If research tools exist, check the category's current launches before the
  originality audit; if not, mark PRELIMINARY.
- Never deliver "10 product ideas" in Mode B — deliver ONE deep invention. Offer
  line-extension as a follow-up.
